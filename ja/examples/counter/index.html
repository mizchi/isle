サンプル一覧 / counter

サーバーが必要

明示的な server action

独立した Counter と、検証・認可を経由する文書名変更を試す。

この例にはサーバーが必要です。GitHub Pages には RPC endpoint を置かず、下の host と実行手順を使います。

独立した Counter と、検証・認可を経由する文書名変更を試す。 host は固定のデモ principal とメモリー内の文書を使う。実認証と、DB の認可・更新の原子性は利用者の server adapter に実装する。

リポジトリ内の例は、ルートで上記コマンドを実行する。検査は just e2e。利用者のアプリへ組み込む場合は npm パッケージの導入手順を使い、このディレクトリのソースと設定を参照する。

実装を読む

app.isle
schema RenameInput { id: string; title: string; }
view DocumentView { id: string; title: string; }
export server action renameDocument(input: RenameInput): DocumentView
  using request: RequestContext
  authorize grant = policy.documentEditor(request, input.id)
  effects { db.write }
{
  return await documents.rename(grant, input.title);
}

export client component Counter(initial: number) {
  state count = initial;
  state unused = 999;
  derive doubled = count * 2;
  <button class="control" type="button">
    on click { count += 1; }
    {count} / {doubled}
  </button>
}

export client component Editor(id: string, initial: string) {
  state title = initial;
  <button class="control" type="button">
    on click async {
      title = (await remote renameDocument({ id, title: title + "!" })).title;
    }
    {title}
  </button>
}
host.mjs
// Local demo only: a fixed server principal, not a login implementation.
const document = { id: 'demo', title: 'Draft', owner: 'alice', tenant: 'demo' };
export const host = {
  context: () => ({ subject: 'alice', tenant: 'demo' }),
  policies: { 'policy.documentEditor': (context, id) => id === document.id && context.subject === document.owner && context.tenant === document.tenant },
  operations: { 'documents.rename': {
    policy: 'policy.documentEditor', effects: ['db.write'],
    prepare: async () => undefined,
    commit: ({ permit, args }) => {
      if (permit.target !== document.id) throw new Error('Wrong resource');
      document.title = args[1];
      return { id: document.id, title: document.title };
    },
  } },
};
