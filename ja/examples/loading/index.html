manifest による読み込み

manifest の先読み判断を調べ、入力時には Search だけが活性化することを確認する。 Network と isle.manifest.json を調べる。Search.edit は取得のみの先読み対象になり、操作まで data-setup は付かない。config の loading を lazy/preload/eager に変えて比較できる。eager は起動時の評価を許す。この例の profile は User Timing を出力する。

リポジトリ内の例は、ルートで上記コマンドを実行する。検査は just examples-check。利用者のアプリへ組み込む場合は npm パッケージの導入手順を使い、このディレクトリのソースと設定を参照する。

実装を読む

app.isle
client component Search() {
  state query = "";
  <section data-search="">
    <label>Search query<input value={query}>on input edit { query = event.value; }</input></label>
    <output aria-live="polite">{query}</output>
  </section>
}
client component Details() {
  state opened = false;
  <section data-details="">
    <button type="button">on click open { opened = true; }Open details</button>
    @if (opened) { <p>Details resumed</p> }
    @else { <p>Details are still inactive</p> }
  </section>
}
server component Page() { <section><Search /><Details /></section> }
setup.mjs
export function setup({ root }) {
  // Observable demo instrumentation; fetching this module alone does not run setup.
  root.setAttribute('data-setup', 'ready');
}
vite.config.mjs
import { exampleConfig } from '../_shared/vite.mjs';
export default exampleConfig(import.meta.url, {
  loading: 'auto', autoPreloadGzipBytes: 8192, handlerChunkBytes: 0, profile: true,
  resources: { Search: './setup.mjs', Details: './setup.mjs' },
  mounts: [{ component: 'Page', props: {}, label: 'Loading policies' }],
});
